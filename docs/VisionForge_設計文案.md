# VisionForge — 本地 No-Code AI 影像模型訓練平台

> **「讓每個人都能鍛造自己的 AI 視覺模型」**

---

## 1. 產品願景與定位

### 1.1 問題陳述

目前訓練影像 AI 模型的門檻極高：使用者需要掌握 Python 程式設計、深度學習框架（PyTorch/TensorFlow）、資料前處理、超參數調整等技能。這使得大量擁有**領域知識**但**缺乏程式能力**的設計師、研究人員、創作者被排除在外。

### 1.2 解決方案

**VisionForge** 是一個本地運行的 No-Code AI 影像模型訓練平台，透過直覺的圖形化介面，讓使用者能夠：

- 📁 匯入並管理影像資料集
- 📷 透過攝影機即時拍攝並擷取訓練資料
- 🏷️ 使用內建工具標註影像（分類標籤、Bounding Box、多邊形）
- 🧠 選擇預訓練模型架構並一鍵啟動訓練
- 📊 即時監控訓練進度與效能指標
- 📦 將訓練完成的模型匯出為 ONNX 格式
- 🚀 **雙模式架構**：包含完整的訓練流程，以及支援 API 伺服器串接的獨立推論模組

### 1.3 目標用戶

| 用戶類型 | 描述 | 核心需求 |
|---------|------|---------|
| 🎨 設計師 / 創作者 | 有基礎 AI 概念，不想寫程式 | 簡單直覺的操作流程 |
| 🔬 領域研究人員 | 有專業知識，需要自訂模型 | 靈活的資料標註與模型選擇 |
| 🏢 小型團隊 | 需要快速原型驗證 | 快速迭代、模型匯出 |

### 1.4 核心價值主張

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│   🖼️ 匯入圖片 ┐                                                │

```

### 3.2 M1 — 專案管理

**功能描述**：管理多個獨立的訓練專案，每個專案包含自己的資料集、標註、模型和訓練歷史。

#### 資料結構

```
project/
├── project.json          # 專案配置檔
├── datasets/
│   ├── raw/              # 原始圖片
│   ├── augmented/        # 增強後圖片
│   └── splits/           # train/val/test 分割
├── annotations/
│   └── annotations.json  # COCO 格式標註檔
├── models/
│   ├── checkpoints/      # 訓練中間點
│   └── exports/          # 匯出的 ONNX 模型
├── logs/
│   └── training_logs/    # TensorBoard 相容日誌
└── configs/
    └── train_config.json # 訓練超參數配置
```

#### 功能清單

| 功能 | 說明 |
|------|------|
| 建立專案 | 選擇任務類型 → 自動建立資料夾結構 |
| 開啟專案 | 從最近專案列表或檔案系統瀏覽 |
| 複製專案 | 複製現有專案作為新實驗的基礎 |
| 匯出/匯入 | 將專案打包為 `.vforge` 壓縮檔分享 |
| 專案儀表板 | 顯示專案狀態概覽（資料量、標註進度、最佳模型） |

### 3.5 M4 — 模型配置與訓練

| 任務類型 | 模型選項 | 參數量級 | 來源 |
|---------|---------|---------|------|

#### 3.5.1 模型架構詳細說明

##### A. 影像分類模型 (torchvision + timm)

所有模型均透過 `torchvision.models` 或 `timm` 函式庫載入，支援 ImageNet 預訓練權重，並自動修改最後一層全連接層以匹配使用者的類別數。

### 3.9 M8 — 推論 API 伺服器 (Inference API Server)

**功能描述**：為了讓使用者可以將訓練好的模型整合到自己寫的程式（如 Python, C#, Node.js）中做後續處理，VisionForge 內建了輕量級的本機推論 REST API 伺服器。

| 功能 | 說明 |
|------|------|
| 一鍵啟動 API | 在介面上點擊即可將當前選定的模型部署為本地 HTTP API 服務 |
| 跨平台呼叫 | 支援以 Base64 或 Multipart 格式發送圖片，回傳 JSON 格式預測結果 |
| API 文件內建 | 系統提供內建的 Swagger UI 或 API 使用範例（包含 Python 呼叫範例） |
| 自動處理前處理 | API 會自動套用該模型訓練時的影像前處理（如 Resize, Normalize） |
| 批次預測 API | 額外提供 Batch 預測端點，支援一次傳入多張圖片 (List of Images) 進行推論，最大化 GPU 平行運算吞吐量 |

#### 本地推論 API 範例

**Request (Python):**
```python
import requests
import base64

with open("test.jpg", "rb") as f:
    img_b64 = base64.b64encode(f.read()).decode("utf-8")

response = requests.post(
    "http://127.0.0.1:8000/api/inference/predict",
    json={"model_id": "resnet50_best", "image_base64": img_b64}
)
print(response.json())
```

**Response (JSON):**
```json
{
  "success": true,
  "inference_time_ms": 14.2,
  "predictions": [
    { "class": "貓", "confidence": 0.942, "bbox": [10, 20, 150, 200] },
    { "class": "狗", "confidence": 0.051, "bbox": null }
  ]
}
```

#### B. 📊 資料品質健檢 (Data Quality Check)

在訓練前自動分析資料集品質，提前發現潛在問題：

| 檢測項目 | 分析方式 | 顯示方式 |
|---------|---------|--------|
| 🔍 模糊圖片 | 計算 Laplacian 方差 | 標記並建議移除 |
| 🖼️ 異常尺寸 | 偏離平均尺寸 > 3倍標準差 | 建議調整或移除 |
| 🎨 色彩異常 | 分析色彩直方圖分布 | 標記過曝/過暗圖片 |
| 🔁 重複圖片 | 感知雜湊 (pHash) 比對 | 列出疑似重複並建議刪除 |
| ⚠️ 類別不平衡 | 計算各類數量比例 | 視覺化分布圖 + 建議操作 |
| 🏷️ 未標註圖片 | 檢查標註完成率 | 進度條 + 快速跳轉未標註圖片 |
| 📀 損壞檔案 | 驗證圖片可讀取性 | 自動標記並隱藏 |

健檢完成後顯示總分（A/B/C/D/F 等級）和具體改善建議。

#### D. 🔄 一鍵重訓練 + A/B 實驗管理

模型訓練後，可快速以不同設定重新訓練並自動追蹤每次實驗：

| 功能 | 說明 |
|------|------|
| 一鍵重訓練 | 基於當前配置，調整部分參數後快速重新訓練 |
| 實驗編號 | 每次訓練自動編號 (#1, #2, #3...) |
| 參數差異標記 | 高亮顯示與前次實驗的參數差異 |
| 實驗註解 | 為每次實驗添加備註（「試試大 batch」「加強增強」等） |
| 時間線回溯 | 視覺化所有實驗的時間線，可快速跳回任意實驗 |

#### E. 📣 智慧通知系統

訓練通常需要數十分鐘到數小時，使用者不可能一直盯著螢幕。

| 通知事件 | 通知方式 | 說明 |
|---------|---------|------|
| 訓練完成 | 🔔 系統通知 + 📧 Email (選配) | 含最終精度、訓練時長 |
| 新最佳模型 | 🔔 系統通知 | 「Epoch 32: 新最佳! Val Acc 94.8%」 |
| 訓練異常 | ⚠️ 彈窗警告 | Loss 異常飆升、NaN 偵測、GPU 過熱 |
| Early Stopping 觸發 | 🔔 系統通知 | 「已自動停止: 10 個 epoch 未改善」 |
| 資料集健檢完成 | 結果摘要 | 「發現 3 個問題，建議處理後再訓練」 |

#### F. 🎬 訓練過程回放 (Training Replay)

訓練完成後，可以「回放」整個訓練過程，觀察模型學習的動態變化：

| 回放內容 | 說明 |
|---------|------|
| Loss/Acc 曲線動畫 | 快速播放整個訓練過程的曲線變化 |
| 每個 Epoch 的預測變化 | 選擇一張圖片，看模型的預測如何隨 Epoch 進化 |
| Grad-CAM 演變 | 觀察模型注意力如何從隨機轉為聚焦特徵 |
| 關鍵事件標記 | 自動標記 "Best Model"、"LR Decay"、"Early Stop" 等時機 |

#### G. 🧩 拖拉式資料處理管線 (Data Pipeline Builder)

視覺化資料前處理流程，讓使用者像拼積木一樣建構資料管線：

```
[輸入圖片] → [調整尺寸 224×224] → [水平翻轉] → [色彩抖動] → [標準化] → [輸出]
                         ↑                      ↑
                   可拖拉新增             可拖拉新增
```

每個處理步驟都有即時預覽，使用者可以看到每一步的輸出結果。

#### H. 📝 訓練日誌摩捷 (Quick Notes)

在訓練監控面板上隨時添加備註，記錄觀察到的現象：

- 「Epoch 15 開始 Loss 不降，可能需要調降 LR」
- 「試試增加資料增強後的效果」
- 「這次用 ConvNeXt 比 ResNet 好很多」

這些筆記會與實驗編號綁定，形成完整的實驗日誌。

```sql
-- 圖片表
CREATE TABLE images (
    id            TEXT PRIMARY KEY,
    project_id    TEXT NOT NULL REFERENCES projects(id),
    filename      TEXT NOT NULL,
    file_path     TEXT NOT NULL,
    width         INTEGER,
    height        INTEGER,
    file_size     INTEGER,               -- bytes
    split         TEXT DEFAULT 'unassigned', -- train|val|test|unassigned
    is_annotated  BOOLEAN DEFAULT FALSE,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 類別標籤表
CREATE TABLE labels (
    id            TEXT PRIMARY KEY,
    project_id    TEXT NOT NULL REFERENCES projects(id),
    name          TEXT NOT NULL,
    color         TEXT NOT NULL,          -- HEX 顏色碼
    shortcut_key  TEXT,                   -- 快捷鍵
    sort_order    INTEGER DEFAULT 0
);

-- 標註表
CREATE TABLE annotations (
    id            TEXT PRIMARY KEY,
    image_id      TEXT NOT NULL REFERENCES images(id),
    label_id      TEXT NOT NULL REFERENCES labels(id),
    annotation_type TEXT NOT NULL,        -- bbox|polygon|keypoint|classification|regression
    data          TEXT NOT NULL,          -- JSON: 座標/數值資料
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 訓練任務表
CREATE TABLE training_runs (
    id            TEXT PRIMARY KEY,
    project_id    TEXT NOT NULL REFERENCES projects(id),
    model_arch    TEXT NOT NULL,          -- resnet50, yolov8s, etc.
    config        TEXT NOT NULL,          -- JSON: 超參數配置
    status        TEXT DEFAULT 'pending', -- pending|running|paused|completed|failed
    started_at    TIMESTAMP,
    completed_at  TIMESTAMP,
    best_metric   REAL,                  -- 最佳驗證指標
    total_epochs  INTEGER,
    current_epoch INTEGER DEFAULT 0,
    checkpoint_path TEXT,
    log_path      TEXT
);

-- 訓練指標記錄表
CREATE TABLE training_metrics (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id        TEXT NOT NULL REFERENCES training_runs(id),
    epoch         INTEGER NOT NULL,
    train_loss    REAL,
    val_loss      REAL,
    train_acc     REAL,
    val_acc       REAL,
    learning_rate REAL,
    epoch_time    REAL,                  -- seconds
    extra_metrics TEXT                   -- JSON: 其他自定指標
);

-- 匯出模型表
CREATE TABLE exported_models (
    id            TEXT PRIMARY KEY,
    run_id        TEXT NOT NULL REFERENCES training_runs(id),
    format        TEXT NOT NULL,          -- onnx
    file_path     TEXT NOT NULL,
    file_size     INTEGER,
    opset_version INTEGER,
    input_shape   TEXT,                  -- JSON
    output_shape  TEXT,                  -- JSON
    metadata      TEXT,                  -- JSON: 額外資訊
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

| 指標 | 目標 |

## 4. 階段性開發計畫 (Phased Implementation Plan)

為了確保 AI 輔助開發的成功率，本專案強烈建議採用「漸進式開發」策略。每次開發衝刺 (Sprint) 僅專注於一個 Phase，確認測試無誤後才進入下一階段。您可以直接複製每個階段的 **[Prompt Hint]** 給 Gemini，引導它專注於當前的任務。

### Phase 1: 基礎設施與介面框架 (Foundation & UI Shell)
- **前端目標**: 建立 Vite + React + TS 專案，實作共用元件庫 (Button, Card, Modal)，完成側邊導覽列與主要版面 (包含 Training / Inference 兩個 Workspaces 的切換路由)。
- **後端目標**: 建立 FastAPI 專案，設定 SQLite 資料庫連線，實作專案 (Project) 的 CRUD REST API。
- **產出目標**: 一個可以執行、可以切換頁面、並能建立與切換新專案的空殼系統。
- **[Prompt Hint 給 Gemini]**:
  > "我們現在要進行 VisionForge 專案的 Phase 1 開發。請幫我初始化前端 (Vite+React+TS) 與後端 (FastAPI)。目標是建立主要 Layout、導覽列，以及實作與後端介接的「建立專案」與「切換專案」功能。請先不要做影像處理與訓練功能，只要確保殼與路由是通的即可。"

### Phase 2: 資料管理與標註模組 (Data & Annotation)
- **前端目標**: 實作 M2 (圖片上傳、攝影機單張擷取預覽) 與 M3 (基於 Canvas 的畫框/分類標籤標註介面)。
- **後端目標**: 處理圖片的儲存邏輯 (檔案系統路由)，實作 COCO 格式標註 JSON 的讀寫 API。
- **產出目標**: 使用者可以成功匯入本機圖片、用攝影機拍一張照片，接著進行畫框標註，並確保重整網頁後標註資料有存在本地端。
- **[Prompt Hint 給 Gemini]**:
  > "現在進行 Phase 2。請針對已經建好的專案，幫我實作 M2 (資料集管理) 與 M3 (影像標註工具)。前端需要實作拖拉上傳與攝影機擷取。請使用 Canvas (或 Fabric.js) 實作 Bounding Box 標註功能，並確保後端能正確讀寫 COCO 格式的 JSON 檔案。"

### Phase 3: 訓練引擎與監控面板 (Training Engine)
- **後端目標**: 實作 PyTorch 訓練迴圈。初期先專注於「基礎影像分類」任務 (例如 ResNet)。實作 WebSocket 推播進度與指標。
- **前端目標**: 實作 M4 (訓練參數設定表單) 與 M5 (訓練監控儀表板，使用 Recharts 畫 Loss/Acc 折線圖)。
- **產出目標**: 能夠從前端選擇模型並啟動訓練，且前端能看到即時跳動的折線圖與 GPU 使用率。
- **[Prompt Hint 給 Gemini]**:
  > "進入 Phase 3，這是核心的訓練引擎。請幫我實作 PyTorch 的影像分類訓練迴圈。後端需要開一個 WebSocket 讓前端能即時收到 Loss 與 Epoch 進度。前端請實作 M4 參數表單，以及使用 Recharts 實作 M5 監控圖表。"

### Phase 4: 模型評估與匯出 (Evaluation & Export)
- **後端目標**: 實作混淆矩陣計算邏輯，以及將 PyTorch `best.pt` 權重轉換匯出為 ONNX 格式的功能。
- **前端目標**: 實作 M6 (模型測試介面與評估報告面板)，並提供一鍵下載 ONNX 檔案的按鈕。
- **產出目標**: 訓練結束後，使用者能直觀檢視模型精準度，並成功將模型匯出到本機。
- **[Prompt Hint 給 Gemini]**:
  > "現在進行 Phase 4。請幫我實作模型訓練完後的評估與匯出功能。後端需要實作計算混淆矩陣，以及 torch.onnx.export 的邏輯。前端請實作 M6 報告面板，並接上 ONNX 下載的 API。"

### Phase 5: 獨立推論與外部串接 (Inference Station & API)
- **前端目標**: 實作 M7 (攝影機即時推論預覽、ROI 關注區域繪製、條件觸發設定介面)。
- **後端目標**: 實作 M7 推論串流邏輯 (包含 OpenCV 即時辨識、MQTT/Webhook 發送)，以及 M8 (單張圖片 REST API 預測端點與 Batch 推論端點)。
- **產出目標**: 一個能接攝影機即時辨識，且能依照使用者設定的條件觸發外部 API / MQTT 的推論工作站。
- **[Prompt Hint 給 Gemini]**:
  > "進入 Phase 5。我們要開發「獨立推論區塊」。請實作 M7 攝影機即時推論，並加上可以畫 ROI 以及設定「條件觸發 Webhook/MQTT」的功能。同時實作 M8 本地推論 API 伺服器，讓外部可以打 API 送圖片來推論。"

### Phase 6: 進階任務與巧思功能 (Advanced Features)
- **目標**: 擴充模型庫 (加入 YOLO 物件偵測等模型)。加入資料增強視覺化、Grad-CAM 熱力圖、資料品質健檢等「額外巧思功能」。
- **產出目標**: 擁有完整且專業功能的 VisionForge 正式版。
- **[Prompt Hint 給 Gemini]**:
  > "來到最後的 Phase 6。系統架構已經很穩定了，現在請幫我將『物件偵測任務 (YOLO)』的支援加進去。接著，請幫我實作 Grad-CAM 的視覺化功能，以及訓練前的資料品質健檢。"
